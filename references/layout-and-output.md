# 版式、源文件与交付

## 询问交付格式

对尚未明确的交付格式，按以下顺序给出常用选项：

1. **仅 PDF**：不交付报告的可编辑源文件。
2. **PDF + Word**：附 .docx 文件。
3. **PDF + LaTeX**：附 .tex 源工程及构建所需资源。
4. **PDF + Typst**：附 .typ 源工程及构建所需资源。
5. **Other（自行输入）**：允许填写其他格式或组合，例如 Markdown（.md）、HTML（.html）、多种源格式，或只要某种源文件。

使用自带自由输入/Other 的询问工具时，只提交前四项为选项，使用工具自带的自由输入入口；不要再塞入一个无法填写的 Other 选项。文本询问时，将“Other（请填写）”列在最后并接收用户的自由文本。已有明确要求不再询问，同一报告补充材料时沿用选择。

课程强制提交源文件而用户选择仅 PDF 时，指出具体冲突并请用户决定。Other 要求清楚时直接执行，只有缺少必要信息或不受现有工具支持时再说明和澄清，不擅自退回常用格式。

## 选择内部制作路径

源文件交付格式由用户选择。选定格式时采用对应工具；仅 PDF 时，内部源格式可根据模板、已有源文件和可用的导出能力决定，保留工作源文件但不默认附到交付包中。以下是制作路径建议，不自动增加交付文件。

| 情况 | 建议路径 |
|---|---|
| 使用官方 DOCX、指定其他 Word 模板，或需要在 Word 中继续编辑 | DOCX + 导出 PDF |
| 用户已有 LaTeX 工程，或课程提供 LaTeX 模板 | 保留 LaTeX 工程 + 编译 PDF |
| 用户已有 Typst 工程，或选择 Typst | 保留 Typst 工程 + 编译 PDF |
| 仅 PDF，且没有模板或既有源工程 | 在可用工具中选择适合内容且能完成渲染验证的一种；公式和图表较多时可采用 Typst 或 LaTeX |

三条路径是可选工作流，并不表示三种编译工具始终可用。任务开始时按需检查环境。源文件的编辑性、公式和图表质量比文件扩展名更重要；不得用整页图片拼成所谓可编辑 DOCX，也不要只改扩展名。

## 通用版式

不使用模板时，默认以 A4、清晰单栏和克制的层级开始，允许内容需要的调整。段落、公式、图表和题注保持一致；不要为复制历史风格强加表格外框、独立封面、目录或双栏。

正文语言同时应用于自拟标题、图题、表题和图例。课程固定栏目、代码、变量和器件型号按其语义保留。选择官方模板时，模板固定英文标签与中文正文可以共存；不因选择中文就擅自改写全部官方栏目。

避免图题与图分离、标题孤立、公式越界、表格被不可读地压缩以及空行造成的大块留白。单页尺寸不足时调整内容布局或合理跨页，不以不断缩小字体解决。

## DOCX

编辑模板副本，保护原文件。优先复用样式、节属性、页眉校标、表格关系和必要的页脚；替换文字时注意不能一并删除公式、图片或字段。标题使用真正的段落样式，公式尽可能保留可编辑结构。

模板若把正文容器做成表格单元格，Word 对单元格内**嵌套表格**的排版属性可能不生效——重复表头、keep-with-next 写了也不起作用，短表格会在表头后断开、标题会留在页脚。这类问题不要靠继续加排版属性或硬分页去修：属性无效，硬分页则在用户后续填入内容时错位。可行的做法是调整前置内容（多数时候是缩小前面的插图）让表格与标题自然落位。导出后必须逐页看实际页面，不能只凭源文件里的属性判断版面是否正确。

如果环境提供 Documents 和 PDF 相关技能，按当前可用的技能说明编辑、渲染和检查；按环境提供的依赖工具定位运行时，不写死本机安装路径。缺少转换工具时不要声称 DOCX 已经生成或验证 PDF。

## LaTeX

保留已有工程的文档类、宏包和构建方式，除非它们妨碍本次要求。新工程采用与语言及模板匹配的引擎；核对中文字体和数学字体可用性。真实编译并检查缺图、缺引用、越界和字体问题。

如使用仅支持独立文档的内置编译器，先核对其限制；包含多文件、图片或文献库的工程需要支持对应资源的编译方式。预览成功与可导出交付 PDF 分别确认。

## Typst

保留用户现有项目和风格。环境提供 typst-author 技能时按需读取；使用当前可用编译器，核对字体、导入和包依赖。实际编译后检查公式、图表引用、分页和缺字。不要未经验证地宣称由 DOCX 重建的模板与原件完全一致。

## 交付内容

按入口选择交付 PDF，并仅在用户选择时附相应可编辑源文件/源工程；用户通过 Other 指定其他组合时遵循其要求。仅 PDF 不代表删除内部源文件，而是不将报告源文件加入正式交付。交付源工程时包含重新构建所需的图片、文献和其他本地依赖，使用相对路径，清除个人绝对路径、临时文件及无关资料。

全局模式仍按约定交付实际用到的分析/绘图代码、参数、必要的处理后数据、图文件，以及一份简短运行说明；这些实验结果附件与报告的可编辑源文件分别处理，询问时简短说明。用户明确只要报告、不要任何附件时，按其要求交付。无需机械建立空目录；仅放实际存在并有用途的文件。已有输入数据如需复制以保证复现，保留其原貌并标明来源。

运行说明写清入口、依赖、命令及关键输入输出；最终检查结果简要报告实际执行了哪些检查及未完成项，不输出冗长工具日志。使用官方模板的源文件中，保留需要的固定栏目，清理填写提示和不适用的样例内容。

原件和新成果分开保存。所选格式无法生成或实际渲染无法完成时，保留工作源文件并交付可用结果，明确原因及剩余步骤；源文件可以作为备选成果向用户说明，不伪装成已完成其选定的交付形式。
